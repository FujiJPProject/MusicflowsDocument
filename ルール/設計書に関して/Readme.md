# 設計書管理ルール

## 基本方針

- 設計書は原則として Markdown で管理する
- 一覧性・集計・計算・フィルタ・ソートが重要な管理資料は Excel で管理する

## Markdown で管理するもの

- 要件定義
- 画面設計書
- API設計書
- DB設計書の説明資料
- アーキテクチャ設計書
- 運用手順書
- 意思決定ログ

## Excel で管理するもの

- ノウハウ
- 進捗表
- 課題管理表
- 画面項目一覧
- API項目一覧
- テーブル項目一覧
- テストケース一覧
- 集計や計算を伴う管理表

## 理由

- Git との相性が良く、差分がテキストで確認できる
- 変更履歴を追いやすく、レビューしやすい
- コードと同じリポジトリで一元管理しやすい
- ファイルを開く待ち時間が短い
- Grep や全文検索をかけやすい
- Markdown はツール依存が小さく、移行しやすい

## 補足ルール

- Markdown の表が大きくなり、可読性が落ちる場合は Excel に切り出す
- 図は draw.io.png を利用する(VSCodeの拡張機能のDraw.io Integrationを追加)
- 画像・図の保存先は images/ に統一する
